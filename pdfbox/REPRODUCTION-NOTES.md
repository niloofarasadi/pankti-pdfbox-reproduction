# PANKTI Reproduction Notes — Apache PDFBox 2.0.21

**Author:** Niloofar Asadi  
**Research Area:** AI-Assisted Software Engineering and Software Testing  
**Experiment:** Reproduction of the PDFBox case study (Section IV.C)

**Reference:** https://arxiv.org/pdf/2012.01198

## 1. Objective

This investigation examines the method-extraction stage of PANKTI
for Apache PDFBox 2.0.21, based on the case study described in
Section IV.C of the reference paper:

https://arxiv.org/pdf/2012.01198

The goal is to document the experimental setup, investigate discrepancies,
and distinguish verified observations from results that have not yet
been fully reproduced.

## 2. Existing Historical Artifacts

The repository contains previously recorded PDFBox experiment results.
These are treated as historical artifacts and are not claimed to have
been regenerated during the current investigation.

Previously recorded results include:

- Instrumented methods: 129
- Invoked methods: 46
- Generated test cases: 13,804
- Executed tests: 1,840
- Passing tests: 1,597
- Failing tests: 243

These figures come from historical experiment notes and should not be
assumed to describe the controlled extraction reported below.

## 3. Extractor Modifications

Two changes were made in the experimental copy of the extractor.

### 3.1 Multidimensional Array Signatures

The original parameter-signature logic represented an array parameter
with a single `[` character, regardless of the number of dimensions.

For `PDAnnotationMarkup.setInkList(float[][])`, the historical extraction
recorded `[F`. The expected JVM descriptor for a two-dimensional float
array is `[[F`.

The experimental implementation was changed to preserve the number of
array dimensions. The controlled extraction recorded `[[F` for this method.

This confirms the correction for the inspected example.

### 3.2 Null Declaring-Type Guard

An experimental null guard was added to `MockableSelector` to prevent a
NullPointerException when an invocation has no declaring-type reference.

The guard returns `false` when that reference is null. This may affect
mockability classification and must therefore be treated as a behavioral
change, not merely as an output-neutral robustness fix.

The experimental build succeeded after these changes.

## 4. Controlled Main-Source Extraction

The controlled extraction was run against:

`pdfbox/src/main/java`

The extractor reported:

- Total methods processed: 5,801
- Extracted methods: 4,204
- Nested invocations on fields or parameters: 2,677

The resulting CSV was saved as:

`controlled-main-only/extracted-methods-pdfbox-main-only-void.csv`

A class-name heuristic found no classes matching the tested naming patterns
`Test...`, `...Test`, `...Tests`, or `...Tester`. This is a naming-based
check, not proof that all possible test code has been excluded.

## 5. Historical Versus Controlled Extraction

The historical extraction contained 6,133 rows. The controlled main-source
extraction contained 4,204 rows.

Using unique keys composed of declaring class, method name, parameter
signature, and return type, the comparison reported:

- Shared signatures: 4,186
- Historical-only signatures: 1,947
- Controlled-only signatures: 18
- Duplicate keys in either dataset: 0

The two inputs cover different source scopes. These counts are diagnostic
and should not be interpreted as a like-for-like reproduction comparison.

## 6. Method-Matching Diagnostic

The historical matching diagnostic reported:

- Eligible Descartes methods: 2,760
- Matched methods: 2,204
- Unmatched methods: 556
- Duplicate matches: 0
- Match rate: approximately 79.86%

After the experimental changes, the diagnostic reported:

- Matched methods: 2,206
- Unmatched methods: 554
- Duplicate matches: 0
- Match rate: approximately 79.93%

Two previously unmatched methods became matchable:

- `PDAnnotationMarkup.setInkList`, with a two-dimensional `float` array
- `ByteTrie.addPath`, with a two-dimensional `byte` array

These observations are consistent with the multidimensional-array signature
correction helping specific matching cases. The overall improvement is small,
and it does not establish that every unmatched method should be extractable.

## 7. Limitations and Reproducibility Status

The current work verifies a targeted signature-generation correction and
records a small improvement in method matching.

However, the historical extraction and controlled main-source extraction
use different source scopes. In addition, the null-declaring-type guard can
change classification behavior.

Therefore, the current evidence does not establish complete reproduction
of all results in the original case study. Historical downstream metrics
must remain separate from measurements generated by the modified extractor.

Any final comparison should document the source scope, code modifications,
input artifacts, and commands used.

## 8. Next Steps
