# Experimental findings

This document summarizes the evidence currently reported in [REPORT.md](../REPORT.md). Results are scoped to the specific artifacts and runs described there.

## 1. Controlled extraction

The controlled extraction targeted PDFBox main source code:

`pdfbox/src/main/java`

| Metric | Result |
|---|---:|
| Methods processed | 5,801 |
| Methods extracted | 4,204 |
| Nested invocations on fields or parameters | 2,677 |

Output artifact:
`controlled-main-only/extracted-methods-pdfbox-main-only-void.csv`

The historical extraction file contained 6,133 rows. Signature comparison (declaring class, method name, parameter signature, and return type) reported:

| Metric | Result |
|---|---:|
| Shared signatures | 4,186 |
| Historical-only signatures | 1,947 |
| Controlled-only signatures | 18 |

**Limitation:** Historical and controlled runs do not have a confirmed identical source scope. The row-count and signature differences cannot be attributed to the array-signature correction alone.

A class-name heuristic using `Test...`, `...Test`, `...Tests`, and `...Tester` did not identify matching classes under the tested patterns. This heuristic does not prove that all test-related code was excluded.

## 2. Array-signature correction

The original logic represented an array parameter with one `[` regardless of dimensionality. The experimental implementation preserves the number of dimensions.

For `PDAnnotationMarkup.setInkList(float[][])`, the historical record used `[F`; the controlled experimental extraction recorded `[[F`.

The matching diagnostic also showed two methods newly matchable after the combined experimental changes:
- `PDAnnotationMarkup.setInkList`
- `ByteTrie.addPath`

This is consistent with the descriptor correction helping these cases, but the run also included the selector guard. The array fix has not yet been isolated as the sole cause.

## 3. Selector null guard

The experimental `MockableSelector` includes a guard for invocations with no declaring-type reference. It returns `false` rather than raising a `NullPointerException`.

This is a separate behavioral change that can affect which methods are classified as mockable. It should not be conflated with the parameter-signature correction.

The experimental Maven build completed successfully. Compilation and packaging do not, by themselves, verify the full reproduction.

## 4. Matching results

The match count increased by two and the match rate increased by approximately 0.07 percentage points.

**Interpretation:** The improvement is small but consistent with the array-descriptor issue affecting at least some matches. Causal attribution remains open because both experimental changes were present.

## 5. Historical downstream reports

The repository's `pdfbox/README.md` and `pdfbox/execution/system-test-report.csv` contain different summaries.

The CSV `TOTAL` row reports 18,291 tests, 17,655 passing, 636 failing, 66 methods marked `well-tested`, and 45 marked `pseudo-tested`. These figures align with the PDFBox system-test results in Table IV of the paper.

These are existing historical artifacts. They must not be described as newly regenerated by this investigation. The separate README figures have unresolved provenance and may refer to another stage, configuration, or artifact version.

## 6. Supported conclusions

1. The inspected original signature logic did not preserve multidimensional-array depth.
2. The experimental extractor generated the expected `[[F` descriptor for the two-dimensional float-array example.
3. The combined experimental changes coincided with two additional matched methods.
4. The current comparison does not isolate the array-signature fix from the selector guard.
5. Historical downstream reports are evidence available in the repository, not proof of a newly reproduced downstream run.

## 7. Next controlled experiment

Use the same PDFBox source scope and inputs in a four-configuration ablation:

| Configuration | Array-signature fix | Null guard |
|---|---:|---:|
| A — baseline | No | No |
| B — signature only | Yes | No |
| C — guard only | No | Yes |
| D — combined | Yes | Yes |

For each run, record source revision, command, source scope, extracted methods, eligible methods, matches, unmatched methods, duplicates, and match rate.

Before broad analysis, add focused regression tests for one-, two-, and three-dimensional primitive arrays and one- and two-dimensional object arrays. Test the selector's null-declaring-type behavior independently.
